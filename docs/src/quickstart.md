# Quick Start

## Prerequisites

Scaffolding requires:

- **Julia 1.10+** (always)
- **Java 11+** + **Node 18+** on `PATH` — only when `spec_url` is set,
  used by `openapi-generator-cli` and (for v2 specs) `swagger2openapi`

End users of the *generated* package never need either — `src/api/` is
committed plain Julia.

## Recommended — Petstore v2

```julia
using PkgTemplates, OpenAPITemplate

t = Template(;
    user = "your-username",
    dir  = pwd(),
    plugins = APIWrapper(;
        spec_url = "https://petstore.swagger.io/v2/swagger.json",
    ),
)
t("PetstoreClient")
```

The plugin auto-detects Swagger 2.0 and converts the spec to OpenAPI 3.0
in place via `npx swagger2openapi`; the original is kept as
`spec/openapi.v2-original.json`. Conversion is required for the docs
site — `vitepress-openapi` only renders OAS 3+.

The v2 demo is the recommended smoke test: every endpoint has a defined
response schema and the demo server reliably returns valid data.

## Alternative — OpenAPI 3.0 (Petstore v3)

```julia
plugins = APIWrapper(;
    spec_url = "https://petstore3.swagger.io/api/v3/openapi.json",
)
```

Be aware that several v3 demo endpoints currently return HTTP 500
(`/pet/findByStatus`, `/store/inventory`, `POST /pet`), and many
operations have incomplete response schemas. Codegen still produces a
working package; cassette tests and docs try-it-out against those
endpoints will fail. Reach for v3 only if your real API uses an OAS 3.x
spec.

## Hand-written-only scaffold

Omit `spec_url` to skip codegen entirely:

```julia
plugins = APIWrapper()
```

The result is the same `src/client/` overlay (auth, errors, retry,
rate-limit, timeout, logging, middleware, pagination, show) and the
test tree, without the generated `src/api/` layer. Useful when you
want to wrap an API by hand or before a spec exists.

## Local-file spec

```julia
plugins = APIWrapper(; spec_url = "/abs/path/to/openapi.yaml")
```

Both `http(s)://` URLs and bare filesystem paths work; YAML and JSON
are both fine.

## Output directory pitfall

!!! warning "`Template` does not use your current working directory"

    PkgTemplates defaults `dir` to `~/.julia/dev`, so without an explicit
    `dir = ...` your package will land in `~/.julia/dev/<PackageName>`
    regardless of where you ran Julia. Pass `dir = pwd()` (or any
    absolute path) to put it elsewhere. The default exists so the result
    is immediately usable via `]dev <name>`.

## What you get

After `t("PetstoreClient")` returns, `./PetstoreClient/` contains:

```text
PetstoreClient/
├── src/
│   ├── PetstoreClient.jl       # umbrella module (exports + includes)
│   ├── api/                    # generated by openapi-generator (OAS-driven)
│   └── client/                 # hand-written: auth, retry, pagination, …
├── spec/openapi.json           # bundled spec (OAS 3 form)
├── gen/regenerate.jl           # dev-time codegen entry point
├── docs/                       # DocumenterVitepress + vitepress-openapi
├── test/                       # auto-walking runtests + cassette skeleton
├── .github/workflows/          # CI, Documentation, regen-check
└── README.md                   # rendered with usage + "what to do next"
```
